Reach your home server, NAS or office PC from anywhere

Mesh Town joins your devices into a private network: the NAS panel, SSH to the home server, remote desktop to the office PC — from any network, with nothing opened on any router.

  • No port forwarding
  • No public IP
  • No server, no accounts

How it works

A laptop in a café reaches the NAS at home; nothing is opened on either router.

  1. Three places

    A NAS at home, a PC at the office, a laptop in a café — each behind its own router, with no ports opened.

  2. One private network

    Each device runs Mesh Town and joins one network: a secret key and a member list signed by the members.

  3. Meeting in a public directory

    The nodes meet on the public DHT, a directory nobody owns, and post small encrypted records only members can read.

  4. Connected directly

    With what they learned there, the nodes get through their routers (NAT) and connect to each other. Every link is encrypted.

  5. Open by name

    The laptop's browser uses the node as its proxy, so http://nas.meshtown opens the NAS web panel. Other programs get a local port.

  6. Out through a member

    A member can let the others leave through its internet connection: a program pointed at the local proxy 127.0.0.1:1080 then leaves from the office address.

  7. On the move

    The laptop moves to a mobile network and reconnects within seconds. Where no direct connection is possible, the office PC, having a public address, passes traffic on.

What you do not have to do

Open ports or set up dynamic DNS.
Nodes get through NAT themselves; only members reach a shared port.
Run a server.
Nodes meet on the public DHT and connect to each other directly.
Create an account.
A network is a key and a member list the members sign; newcomers join by invite.
Set up DNS.
Shared panels open by name through the node's proxy; other ports appear locally.
Reconnect by hand.
A device that changes networks is back with the others within seconds.

Not the tool if you need

  • a whole subnet joined — Mesh Town shares program ports and adds no virtual network adapter;
  • an iPhone or iPad app — they can use a router running Mesh Town;
  • anonymity — members you invite are trusted, and an exit sees which hosts you connect to.

One local proxy, two uses

The node runs a proxy at 127.0.0.1:1080, SOCKS5 and HTTP on one port.

Names

A shared web panel opens at http://<device-name>.meshtown; the node serves a PAC file that sets this up in the browser.

Exit through a member

A member can agree to be an exit: connections through the proxy then leave from its address, for a service that accepts only your office IP. The exit sees the hosts you connect to.

Install

Pick your system.

macOS

  1. Install:

    Homebrew

    brew install mesh-town/macos/meshtown
meshtown

    App

    Download for Apple silicon or Intel, unzip and move MeshTown.app to Applications. The app is not notarized: on the first launch press Open Anyway in System Settings → Privacy & Security.

  2. Start Mesh Town, open the node page from the menu bar icon and set a password.
  3. Press Create a new network, or Join with an invite from a member; Invite a member shows a link and a QR code.
Open shared web panels by name

In your system's proxy settings, turn on automatic proxy configuration (PAC) and paste http://127.0.0.1:1080/proxy.pac. A shared panel then opens at http://<device-name>.meshtown. For other programs, press Open on this computer next to a shared port on the node page.

Under the hood

The short version; open a line for details.

Discovery: an encrypted record in the public DHT

Every network node knows the network key. From it the node derives a place in the public DHT (HyperDHT, a distributed directory nobody owns) and publishes a small record there about once a minute: the list of member nodes, encrypted with ChaCha20-Poly1305. Without the key, one sees only a public signing key, a salt and ciphertext.

Connection: direct NAT hole punching; relay only through your own member

Nodes connect by NAT hole punching, so home routers and most NATs let the connection through with no port opened. If that fails, a member of the same network with a public address relays the connection; nobody outside the network does. A network where every device is behind NAT has no such member, and some mobile operators prevent direct connections.

Encryption: UDX streams with Noise, plus a handshake on the network secret

Each connection is an encrypted stream: UDX is a reliable transport over UDP, Noise a well-studied framework for encrypted, authenticated connections. On top of it the nodes run a handshake that checks both sides know the network secret; a node that fails it is disconnected. A stranger who learns a node's id gets an answer only from the sign-in and invite services.

Membership: a private key, administrators and single-use invites

A network is a key you keep private: a label you choose plus a random part of about 130 bits. Whoever creates the network is its first administrator, and only administrators invite. An invite is a single-use string, valid for a day, that does not contain the network key. One node can be in up to 8 networks. The node page shows an invite as a link and a QR code (Invite a member); on Android, Scan QR reads it.

Programs and names: a SOCKS5/HTTP proxy on 127.0.0.1:1080, a local port, http://<device-name>.meshtown

Programs reach the network through the node's proxy at 127.0.0.1:1080 (SOCKS5, a standard proxy protocol, and HTTP on one port), or through a local port: Open on this computer turns a member's port 22 into 127.0.0.1:2022. A device shares program ports running on it, TCP or UDP, with all members or selected ones. The node's own page is at http://127.0.0.1:7777: plain HTTP, reachable from your local network unless you run meshtown access localhost. Never share the page port.

A shared web interface is at http://<device-name>.meshtown. The device name is folded to lowercase ASCII letters, digits and dashes — "Café Router" becomes cafe-router — and two devices with the same name get a short suffix from their id. A port other than 80 is written as usual: http://nas.meshtown:8080. Names work only through the node's proxy, and only over http://.

Limits: ports, not networks; UDP over reliable streams; no iPhone app
  • Ports, not networks. Mesh Town connects TCP and UDP program ports on the device itself. There is no virtual network interface, no subnet routing and no capture of all traffic.
  • Programs use the proxy. A program has to work through a SOCKS5 or HTTP proxy, or connect to a local port on 127.0.0.1.
  • UDP rides on reliable streams. Order is kept, but a stalled link delays everything behind it, and a datagram larger than 2048 bytes is truncated.
  • Trust, not anonymity. Members you invite are trusted, and an exit sees which hosts you connect to. There is no iPhone or iPad app. They can use Mesh Town on a router.
  • Early software. Releases of the 0.3.x line are a working network node, not a hardened product.

Questions

Does it route all my traffic?

No. Mesh Town connects program ports: a program reaches the network through the node's proxy or a local port. There is no virtual network interface, and other traffic is not touched.

What if two devices cannot connect directly?

A member of your network with a public address relays between them. With no such member they stay unconnected. Behind home routers and most NATs a direct connection works; some mobile operators prevent it.

Who can reach the services I share?

Only members of your network, and for each port you choose: all members or selected ones. A port is shared only after you publish it.

Can I share my network key instead of invites?

Better not. The key and the settings file are secret. Invite people with single-use invites, and hand them over in person.

Is it free and open source?

Yes, under AGPL-3.0-only. Peer discovery and transport come from townjump, a Rust port of Holesail.
