Reach your devices from anywhere

Mesh Town connects your computers, phones and routers into a private network, so the web panel of a NAS, SSH to a home server or RDP to the office machine is one link away — from a café, a train or another country. No port forwarding, no central server, no accounts.

Install Mesh Town See how it works

Free and open source (AGPL-3.0-only). For macOS, Windows, Linux, Android, OpenWrt and Keenetic routers. Early releases: a working network node, not a hardened product.

How Mesh Town connects your devices

Want the details? Read how it works below, or the architecture notes.

Why people use it

  • Your devices, from anywhere

    SSH to a home server, RDP to the office machine, the web panel of a NAS or router — from any network you happen to be on.

  • No port forwarding

    Nothing to open on the router, no public IP, no dynamic DNS. Only members of your network reach a shared port.

  • No server, no accounts

    Nodes meet on the public DHT, a directory nobody owns. A network is a secret key and a member list signed by its members. Newcomers join with a single-use invite.

  • Survives a change of network

    Wi-Fi, mobile data, a hotel network: the node notices the switch and reconnects to the others within seconds.

Who it is for

  • Homelab owners — a Raspberry Pi, a NAS or Home Assistant behind a home router.
  • Sysadmins — machines at clients' or relatives' places, each behind its own NAT, reached over SSH or RDP.
  • Small teams — a development database, an internal web tool or a build machine shared with a few people.

Not for you if you want whole networks joined rather than single services (Mesh Town adds no virtual network adapter), use an iPhone or iPad, or want anonymity.

Install in 3 steps

Pick your system. The full guide for each one has checks and troubleshooting.

macOS

  1. Install with Homebrew:
    brew install mesh-town/meshtown/meshtown
    Or download the app for Apple silicon or Intel from the full guide.
  2. Run meshtown. Open the node page from the menu bar icon and set a password.
  3. Press Create a new network, or Join with an invite from a member. The node page shows an invite as a link and a QR code (Invite a member). Then set the browser's proxy to 127.0.0.1, port 1080, and shared web interfaces open at http://<device-name>.meshtown. While the proxy is set, the browser reaches every site through the node, so keep Mesh Town running; if you stop it, remove the proxy.

How it works

Mesh Town is a node program that runs on each of your devices. Here is what happens under the hood.

Finding each other

Every node of a network knows the network key. From it the node derives a place in the public DHT (HyperDHT, a distributed directory nobody owns) and publishes a small record there about once a minute: the list of member nodes, encrypted with ChaCha20-Poly1305. Without the key, one sees only a public signing key, a salt and ciphertext.

Getting through NAT

Nodes connect by NAT hole punching, so home routers and most NATs let the connection through with no port opened. There is no relay fallback: if two nodes cannot punch through, they stay unconnected. Some mobile operators prevent direct connections.

Encryption and admission

Each connection is an encrypted stream (UDX with Noise). On top of it the nodes run a handshake that checks both sides know the network secret; a node that fails it is disconnected. A stranger who learns a node's id gets an answer only from the sign-in and invite services.

Members and invites

A network is a key you keep private: a label you choose plus a random part of about 130 bits. Whoever creates the network is its first administrator, and only administrators invite. An invite is a single-use string, valid for a day, that does not contain the network key. One node can be in up to 8 networks. The node page shows an invite as a link and a QR code (Invite a member); on Android, Scan QR reads it.

Names and addresses

A shared web interface is at http://<device-name>.meshtown. The device name is folded to lowercase ASCII letters, digits and dashes — "Café Router" becomes cafe-router — and two devices with the same name get a short suffix from their id. A port other than 80 is written as usual: http://nas.meshtown:8080. Names work only through the node's proxy, and only over http://.

Proxy, ports and the node page

Programs reach the network through the node's proxy at 127.0.0.1:1080 (SOCKS5 and HTTP on one port), or through a local port: Open on this computer turns a member's port 22 into 127.0.0.1:2022. A device shares ports of programs running on it, TCP or UDP, with all members or selected ones. The node's own page is at http://127.0.0.1:7777: plain HTTP, reachable from your local network unless you run meshtown access localhost. Never share the page port.

Exit through a member

A member can also agree to be an exit: the others then send traffic out through its internet connection via the proxy, for example to reach a service that accepts connections only from your office IP. The exit sees which hosts you connect to.

How it differs

Mesh Town compared with the usual ways to reach a device at home
The usual wayWith Mesh Town
Port forwarding and dynamic DNSNothing to open: only members reach the port
A tunnel server of your ownNo server: members connect to each other directly
A tunnel or relay serviceNo account, no provider in the middle
A mesh with a coordination serverThe member list lives with the members

Limitations, honestly

  • Ports, not networks. Mesh Town connects TCP and UDP ports of programs on the device itself. There is no virtual network interface, no subnet routing and no capture of all traffic.
  • Programs use the proxy. A program has to work through a SOCKS5 or HTTP proxy, or connect to a local port on 127.0.0.1.
  • No relay. If a network prevents direct connections, as some mobile operators do, the node cannot reach the others from there.
  • UDP rides on reliable streams. Order is kept, but a stalled link delays everything behind it, and a datagram larger than 2048 bytes is truncated.
  • Trust, not anonymity. Members you invite are trusted, and an exit sees which hosts you connect to. There is no iPhone or iPad app.
  • Early software. Releases of the 0.3.x line are a working network node, not a hardened product.

Questions

Does it route all my traffic?

No. Mesh Town connects ports of programs: a program reaches the network through the node's proxy or a local port. There is no virtual network interface, and other traffic is not touched.

Do I need a server, a public IP or an account?

No. Nodes find each other on the public DHT and connect directly. A network is a secret key plus a member list kept by the members.

What if two devices cannot connect directly?

They stay unconnected: there is no relay to fall back on. Behind home routers and most NATs it works; some mobile operators prevent it.

Who can reach the services I share?

Only members of your network, and for each port you choose: all members or selected ones. A port is shared only after you publish it.

What happens when my laptop changes networks?

The node notices the switch and reconnects to the others within seconds. Connections open at that moment are closed and reopened by the program.

Can I share my network key instead of invites?

Better not. The key and the settings file are secret. Invite people with single-use invites, and hand them over in person.

Does it work on iPhone or iPad?

No. It runs on macOS, Windows, Linux, Android, and OpenWrt or Keenetic routers.

Is it open source?

Yes, under AGPL-3.0-only. Peer discovery and transport come from townjump, a Rust port of Holesail.
